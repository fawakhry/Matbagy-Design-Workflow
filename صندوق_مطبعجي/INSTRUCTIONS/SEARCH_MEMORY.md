# البحث في ذاكرة صندوق مطبعجي

## الهدف

عند وصول طلب تصميم جديد، استخدم الحالات القديمة كخبرة مساعدة لا كمصدر حقيقة نهائية.

## ترتيب البحث

1. نفس العميل إن كانت هويته مؤكدة.
2. نفس نوع المنتج.
3. نفس المقاس أو التكوين.
4. نفس الكلمات المفتاحية/الستايل.
5. حالات FINAL_APPROVED أولًا.
6. حالات EXPLICITLY_LIKED ثم PARTIAL_ACCEPTANCE.
7. استخدم REJECTED فقط كأمثلة سلبية لما يجب تجنبه.

## ما الذي تستخرجه من النتائج؟

- أنماط التكوين التي نجحت.
- قواعد النصوص والمقاسات.
- تفضيلات الألوان والخطوط.
- الأشياء التي تكرر رفضها.
- تعليمات المحافظة على الصور/الملامح.
- عدد التعديلات المعتاد إن كان له معنى.
- أمثلة مشابهة قابلة لإعادة الاستخدام.

## ممنوع

- لا تفترض أن عميلًا جديدًا له نفس ذوق عميل سابق.
- لا تنقل بيانات شخصية من عميل إلى آخر.
- لا تستخدم تصميمًا مرفوضًا كمثال إيجابي.
- لا تعتبر ذاكرة الصندوق بديلًا عن طلب العميل الحالي.
- لا تعتبر الـAI مصدرًا لحقائق Order/Payment/Production الحية.

## المخرج المفضل للمصمم الذكي

قبل التنفيذ، كوّن داخليًا Design Context مختصرًا:

- Current Request
- Similar Approved Cases
- Relevant Reusable Rules
- Negative Patterns To Avoid
- Confidence

ثم نفذ الطلب الحالي مع إعطاء طلب العميل الحالي الأولوية الأعلى.
