# 3) Lifecycle + Versions + Truth Separation

المراحل الرسمية:

`OPEN | UNDER_REVIEW | REVISION_REQUIRED | WAITING_CUSTOMER_APPROVAL | FINAL_APPROVED | CLOSED | REOPENED`

لا يجوز لأي AI نقل Case إلى `FINAL_APPROVED` أو `CLOSED` من نفسه.

افصل دائمًا بين:
- `CUSTOMER_FACT`
- `OWNER_DECISION`
- `CHATGPT_OPINION`
- `GEMINI_OPINION`
- `SYSTEM_STATE`
- `INFERRED`
- `UNKNOWN`

كل نسخة تصميم مستقلة تأخذ:

`V1`, `V2`, `V3` ...

لا تمسح النسخ القديمة ولا الخلافات بين ChatGPT وGemini.

المرجع:

`SCHEMA/CASE_LIFECYCLE_AND_LEARNING.md`

# 6) بعد الموافقة على Case

1. أنشئ/استخدم Case ID النهائي.
2. استخدم Project Root الرسمي فقط.
3. أنشئ/استخدم `01_Design_Cases/YYYY/<CASE_ID>/`.
4. خصص Asset IDs النهائية.
5. ارفع كل صورة متاحة فعليًا.
6. سجّل Drive File ID الحقيقي + الروابط + أسماء الملفات.
7. إذا الملف غير متاح، سجّل `PENDING_UPLOAD` ولا تدّعِ الرفع.
8. حدّث Case/Room storage metadata.

---

# 7) استدعاء شغل قديم

عند طلب Case أو تصميم أو صورة قديمة:

1. ابحث داخل `CASES/`.
2. استخدم Case ID / Order ID / المنتج / المقاس / الكلمات / البحث الدلالي.
3. اقرأ الحالة كاملة وRoom/Storage manifest عند وجوده.
4. لأي Asset = `LINKED` استخدم Drive File ID.
5. ميّز original / reference / generated_result / final_approved.
6. أولوية التعلم:

`FINAL_APPROVED > EXPLICITLY_LIKED > PARTIAL_ACCEPTANCE > REJECTED`

7. REJECTED = Negative Learning فقط.

# 10) Knowledge Extraction — عقل مطبعجي المتراكم

الصندوق ليس أرشيفًا فقط.

بعد إغلاق Case:

`FINAL_APPROVED -> CLOSED -> KNOWLEDGE_EXTRACTION -> CANDIDATES -> VALIDATION -> PROMOTION`

أو:

`CLOSED -> NO_REUSABLE_KNOWLEDGE`

لا يتحول رأي AI وحده إلى Global Rule.

كل Knowledge يجب أن ترتبط بـCase/Version/Evidence.

الرفض والفشل يبقيان Negative Learning.

العقد:

`SCHEMA/KNOWLEDGE_EXTRACTION_CONTRACT.md`

السجل المركزي:

`KNOWLEDGE/INDEX.md`

مصادر مستقبلية محتملة:
- ChatGPT design chats.
- Gemini reviews.
- WhatsApp بعد الربط المصرح به.
- Proof approvals.
- ملفات التصميم على أجهزة العمل بعد Ingestion منظم.
- Google Drive assets.
- TrendOS Order Context عبر source-of-truth connectors.

# 11) قاعدة الحقيقة

- لا تعتبر آخر صورة Final إلا بدليل.
- إذا لم توجد موافقة نهائية: `NOT_CONFIRMED`.
- لا تخترع Order ID أو Customer أو Size أو Asset/Drive link أو Approval.
- لا تقل إن ملفًا رفع إلى Drive بدون File ID حقيقي.
- حقائق Order/Payment/Production/Inventory/Delivery الحية تأتي من TrendOS source-of-truth، وليس AI memory.

---

# 12) الخصوصية والأمان

- صور العملاء الحقيقية لا تحفظ داخل GitHub العام.
- GitHub يحفظ metadata/cases/rules/links فقط.
- الصور الفعلية تحفظ في Google Drive تحت Project Root.
- لا تحفظ API Keys أو Tokens أو Passwords أو Secrets داخل Cases أو Prompts العامة.
- Customer-only knowledge لا تطبق على عميل آخر.
