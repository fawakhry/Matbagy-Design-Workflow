# صندوق مطبعجي — اقرأني أولاً

> هذا هو المدخل الرسمي والوحيد لتشغيل ذاكرة التصميمات الخاصة بمطبعجي.
> صندوق مطبعجي مستقل تمامًا عن الصندوق الأسود لترند مول / TrendOS.

## البرومبت البشري الوحيد

من الآن المستخدم لا يحتاج لكتابة أي تعليمات طويلة.

العبارة المعتمدة الوحيدة هي:

`ادخل جيت هب صندوق مطبعجي`

عندما يكتب المستخدم هذه العبارة أو ما يعادلها بوضوح، يجب على الـAI أن:

1. يفتح Repository: `fawakhry/Matbagy-Design-Workflow`.
2. يستخدم الفرع: `agent/initial-mvp`.
3. يبدأ من `صندوق_مطبعجي.md` ثم يقرأ هذا الملف كاملًا.
4. يقرأ الملفات الداخلية اللازمة حسب المهمة بدون أن يطلب من المستخدم نسخ أي Prompt إضافي.
5. يحدد هدف المستخدم من سياق المحادثة: استخراج شات / مراجعة Draft / تسجيل / تحديث حالة موجودة / ربط صور / استدعاء حالة قديمة / بحث عن شغل مشابه.
6. ينفذ المهمة طبقًا للقواعد التالية.

# 1) إذا كانت المحادثة تحتوي على شغل تصميم قديم أو حالي

اقرأ المحادثة الحالية كاملة من أول رسالة إلى آخر رسالة متاحة.

استخرج كل Design Case مستقلة، وافصل الحالات المختلفة عن بعضها. لا تخلط شغلين مختلفين في Case واحدة إلا إذا كانا بوضوح جزءًا من نفس طلب التصميم.

لكل Case استخرج فقط ما تدعمه المحادثة:

- طلب العميل الأصلي.
- النصوص المطلوبة حرفيًا.
- نوع المنتج/المطبوع.
- المقاس والوحدة والكمية إن وجدت.
- الصور الأصلية المرسلة ودور كل صورة.
- الصور المرجعية ودورها.
- تعليمات التكوين/layout.
- الألوان والخطوط والأسلوب إن ذكرت.
- Must Keep.
- Must Avoid.
- كل المحاولات والنتائج بالترتيب.
- البرومبتات أو التعليمات المستخدمة إن كانت ظاهرة.
- Feedback المستخدم بعد كل محاولة.
- التعديلات المطلوبة بعد كل نتيجة.
- ما تم قبوله صراحة.
- ما تم رفضه صراحة.
- النسخة النهائية فقط إذا كانت مؤكدة.
- Order ID إذا كان ظاهرًا بوضوح فقط.
- Reusable Rules.
- Search Tags.

استخدم `SCHEMA/DESIGN_CASE_SCHEMA.md` و`SCHEMA/ASSET_LINKING_CONTRACT.md` كقواعد داخلية إلزامية.

## منع التكرار

قبل إنشاء Case جديدة، ابحث داخل `صندوق_مطبعجي/CASES/` عن حالة مطابقة أو نفس الشات/الشغل.

إذا كانت الحالة موجودة بالفعل:

- لا تنشئ Case ID جديدة.
- استخدم نفس Case ID.
- نفّذ Update أو Backfill فقط.
- حافظ على الـTimeline والتاريخ السابق.

إذا لم توجد حالة مطابقة، أنشئ Case جديدة بعد موافقة المستخدم.

# 2) بوابة المراجعة البشرية

عند استخراج شات:

- أنشئ Draft أولًا.
- اعرض كل Design Case بشكل منظم.
- اعرض Assets Map ودور كل صورة.
- أبرز `EXPLICIT` و`INFERRED` و`UNKNOWN`.
- لا تسجل Case جديدة ولا ترفع صورًا قبل موافقة المستخدم الصريحة.

الموافقة الصريحة مثل:

`تمام سجل`

أو:

`اعتمد وسجل`

بعد الموافقة فقط، أكمل الحفظ والربط تلقائيًا قدر ما تسمح به الأدوات، بدون طلب إعادة معلومات موجودة بالفعل في المحادثة.

---

# 3) مفاتيح الربط الثابتة

## Case ID

المفتاح الأساسي لذاكرة التصميم:

`DESIGN-YYYY-NNNNNN`

مثال:

`DESIGN-2026-000001`

## Order ID

يسجل فقط إذا كان موجودًا بوضوح في المحادثة أو مصدر موثوق.

إذا لم يوجد:

`order_id: UNKNOWN`

يمكن إضافته لاحقًا بدون تغيير Case ID.

Order ID ليس بديلًا عن Case ID لأن أوردر واحد قد يحتوي أكثر من Design Case.

## Asset ID

كل صورة أو ملف مرئي داخل الحالة يأخذ Asset ID مستقلًا.

بعد حفظ الـCase:

`<CASE_ID>-A001`
`<CASE_ID>-A002`
`<CASE_ID>-A003`

أثناء الـDraft يمكن استخدام:

`DRAFT-A001`
`DRAFT-A002`

ثم تحويلها إلى Asset IDs نهائية عند الحفظ.

لكل Asset يجب معرفة:

- `asset_id`
- `case_id`
- `order_id`
- `source_role`
- `conversation_position`
- `purpose`
- `instructions`
- `attempt_id` إن وجد
- `derived_from_asset_id` إن وجد
- `privacy_class`
- `asset_binding_status`
- `storage_provider`
- `storage_ref`
- Google Drive File ID عند الربط الفعلي

الأدوار القياسية للصور:

- `customer_original`
- `reference_design`
- `generated_result`
- `final_approved`
- `unknown`

# 4) Google Drive هو مخزن الصور الرسمي

تم اعتماد Google Drive كمكان الصور والملفات المرئية الخاصة بصندوق مطبعجي.

## Root Folder

- الاسم: `صندوق مطبعجي - الصور`
- Folder ID: `1qhoxC_c2MF3X_hhHcWiDo2SzW2ySCch_`

## مجلد 2026

- الاسم: `2026`
- Folder ID: `1AP68g1gP0S3fNNzgyOkithg3VfH4kEgE`

## هيكل التخزين

`صندوق مطبعجي - الصور/YYYY/<CASE_ID>/`

لكل Case محفوظة، أنشئ أو استخدم مجلدًا باسم Case ID داخل مجلد السنة.

يفضل تسمية الملفات بما يبدأ بـAsset ID، مثل:

`DESIGN-2026-000125-A001__original.jpg`
`DESIGN-2026-000125-A002__reference.png`
`DESIGN-2026-000125-A003__final.png`

لكن الربط الحقيقي لا يعتمد على اسم الملف فقط؛ يعتمد على Google Drive File ID المسجل داخل Asset Record.

## حالات الصور

- `LINKED`: الملف موجود في Google Drive وDrive File ID مسجل.
- `PENDING_UPLOAD`: الـAsset معروف لكن الملف نفسه لم يرفع بعد.
- `MISSING`: الملف كان متوقعًا لكنه غير متاح أو تعذر العثور عليه.
- `REMOVED`: تم حذفه عمدًا مع الاحتفاظ بالأثر التاريخي.

القيمة الرسمية لمكان التخزين:

`storage_provider: GOOGLE_DRIVE`

إذا لم يرفع الملف بعد:

`asset_binding_status: PENDING_UPLOAD`

## قاعدة رفع الصور بعد الموافقة

1. أنشئ أو استخدم Case ID النهائي.
2. أنشئ أو استخدم مجلد السنة.
3. أنشئ أو استخدم مجلد Case ID.
4. لكل صورة متاحة فعليًا من المحادثة، ارفعها إلى مجلد الـCase إذا كانت الأدوات تسمح بالوصول إلى ملفها/bytes.
5. سجل Google Drive File ID الحقيقي واسم الملف والمجلد في Asset Record.
6. إذا الصورة ظاهرة في تاريخ الشات لكن ملفها نفسه غير متاح للأداة، لا تدّعِ رفعها؛ سجلها `PENDING_UPLOAD` مع الحفاظ على Asset ID ووصفها وموضعها في الشات.
7. لا تعيد استخراج الشات لاحقًا بسبب الصور؛ يتم فقط استكمال الربط بين Asset ID وGoogle Drive File ID.

# 5) إذا كان المستخدم يريد استدعاء شغل قديم

إذا طلب المستخدم استدعاء Case أو تصميم أو صورة قديمة، أو قال مثلًا "هات الشغل القديم" أو "هات التصميم اللي شبه كذا":

1. ابحث أولًا داخل `صندوق_مطبعجي/CASES/`.
2. استخدم Case ID أو Order ID أو نوع المنتج أو المقاس أو الكلمات المفتاحية أو البحث الدلالي.
3. اقرأ الحالات المطابقة كاملة.
4. اقرأ Assets Map لكل حالة.
5. لأي Asset حالته `LINKED`، استخدم Google Drive File ID لاسترجاع الصورة أو الملف من Google Drive.
6. ميّز بين original وreference وgenerated_result وfinal_approved.
7. أعط الأولوية للحالات بهذا الترتيب:
   `FINAL_APPROVED > EXPLICITLY_LIKED > PARTIAL_ACCEPTANCE > REJECTED`
8. استخدم REJECTED كخبرة سلبية فقط لما يجب تجنبه.
9. لا تخلط صور أو بيانات Case بأخرى.
10. إذا وجدت Asset حالته `PENDING_UPLOAD`، قل بوضوح إن سجل الصورة موجود لكن الملف نفسه لم يتم ربطه فعليًا على Drive بعد.

# 6) قاعدة الحقيقة

- لا تعتبر آخر صورة Final إلا إذا كان هناك دليل واضح على اعتمادها.
- إذا لم توجد موافقة نهائية، استخدم `NOT_CONFIRMED`.
- لا تخترع Order ID أو اسم عميل أو مقاس أو رابط صورة أو موافقة.
- لا تقل إن صورة رفعت إلى Google Drive إلا إذا حصلت على File ID فعلي.
- افصل دائمًا بين:
  - `EXPLICIT`
  - `INFERRED`
  - `UNKNOWN`
- إذا كان الربط بين ملف وصورة غير مؤكد، لا تربطه خطأ؛ اتركه `PENDING_UPLOAD` أو `MISSING` حسب الحالة.

---

# 7) الخصوصية

- صور العملاء الحقيقية لا تحفظ داخل GitHub العام.
- GitHub يحفظ الـCase records والـmetadata وقواعد التعلم فقط.
- الصور الفعلية تحفظ في Google Drive.
- لا تحفظ API Keys أو Tokens أو Passwords أو Secrets داخل الـCase.
