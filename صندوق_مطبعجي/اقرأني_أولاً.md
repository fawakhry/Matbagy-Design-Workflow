# صندوق مطبعجي

> **المدخل الرسمي لذاكرة التصميمات الخاصة بمطبعجي.**
>
> هذا الصندوق مستقل تمامًا عن **الصندوق الأسود لترند مول / TrendOS**. الصندوق الأسود خاص بذاكرة المشاريع والتنفيذ، أما **صندوق مطبعجي** فهو خاص بخبرة التصميمات: طلبات العملاء، الصور، المراجع، المحاولات، التعديلات، الرفض، القبول، والنتائج النهائية.

## قاعدة التشغيل الموحدة

من الآن يوجد **برومبت واحد فقط للاستخدام البشري**:

`PROMPTS/MASTER_PROMPT.md`

البرومبت الواحد يغطي أربع وظائف، ويحدد الوظيفة من كلام المستخدم والسياق:

1. استخراج شات قديم أو حالي إلى Design Cases.
2. عرض Draft للمراجعة قبل التسجيل.
3. بعد موافقة المستخدم: تسجيل الحالة وربط/رفع الصور المتاحة إلى Google Drive.
4. استدعاء حالة أو تصميم سابق والبحث في الذاكرة والصور المرتبطة به.

لا يحتاج المستخدم إلى حفظ Prompts مختلفة لكل مرحلة.

## ترتيب القراءة الإلزامي للـAI

عند الوصول إلى صندوق مطبعجي:

1. اقرأ هذا الملف كاملًا.
2. اقرأ `SCHEMA/DESIGN_CASE_SCHEMA.md`.
3. اقرأ `SCHEMA/ASSET_LINKING_CONTRACT.md`.
4. عند استخراج محادثة اقرأ `INSTRUCTIONS/EXTRACT_OLD_CHAT.md`.
5. عند الحفظ بعد موافقة المستخدم اقرأ `INSTRUCTIONS/SAVE_APPROVED_CASE.md`.
6. عند الاستدعاء أو البحث اقرأ `INSTRUCTIONS/SEARCH_MEMORY.md`.
7. استخدم `PROMPTS/MASTER_PROMPT.md` كمرجع الأمر الموحد.

## بوابة المراجعة البشرية

عند استخراج شات:

- اقرأ المحادثة كاملة من أول رسالة إلى آخر رسالة متاحة.
- افصل كل Design Case مستقلة عن الأخرى.
- اعرض Draft كاملًا أولًا.
- **ممنوع تسجيل Case جديدة أو رفع صورها قبل موافقة المستخدم الصريحة** مثل `تمام سجل` أو `اعتمد وسجل`.

بعد الموافقة، أكمل الحفظ والربط تلقائيًا قدر ما تسمح به الأدوات المتاحة، بدون أن تطلب من المستخدم إعادة معلومات موجودة بالفعل.

## المفاتيح الثابتة

### Case ID

المفتاح الأساسي لذاكرة التصميم:

`DESIGN-YYYY-NNNNNN`

مثال:

`DESIGN-2026-000001`

### Order ID

يسجل فقط إذا كان موجودًا بوضوح في المحادثة أو مصدر موثوق.

إذا لم يوجد:

`order_id: UNKNOWN`

يمكن إضافته لاحقًا بدون تغيير Case ID.

**Order ID ليس بديلًا عن Case ID** لأن أوردر واحد قد يحتوي أكثر من Design Case.

### Asset ID

كل صورة/ملف مرئي داخل الحالة يأخذ معرفًا مستقلًا:

`<CASE_ID>-A001`
`<CASE_ID>-A002`
...

أثناء الـDraft يمكن استخدام `DRAFT-A001` ثم تحويله إلى Asset ID نهائي عند الحفظ.

## Google Drive هو مخزن الصور الرسمي

تم اعتماد Google Drive كمكان الصور والملفات المرئية الخاصة بصندوق مطبعجي.

### Root Folder

- الاسم: `صندوق مطبعجي - الصور`
- Folder ID: `1qhoxC_c2MF3X_hhHcWiDo2SzW2ySCch_`

### 2026 Folder

- الاسم: `2026`
- Folder ID: `1AP68g1gP0S3fNNzgyOkithg3VfH4kEgE`

### هيكل التخزين

لكل Case محفوظة ينشأ مجلد باسم Case ID داخل مجلد السنة:

`صندوق مطبعجي - الصور/YYYY/<CASE_ID>/`

ويفضل أن تسمى الملفات بطريقة تبدأ بـAsset ID، مثل:

`DESIGN-2026-000125-A001__original.jpg`
`DESIGN-2026-000125-A002__reference.png`
`DESIGN-2026-000125-A003__final.png`

لا يعتمد الربط على اسم الملف وحده؛ المرجع الأساسي هو Google Drive File ID المحفوظ في Asset Record.

## حالات ربط الصور

- `LINKED`: الملف موجود في Google Drive وDrive File ID مسجل.
- `PENDING_UPLOAD`: الـAsset معروف لكن الملف نفسه لم يُرفع بعد رغم اعتماد Google Drive كمخزن.
- `MISSING`: كان متوقعًا وجود ملف ولم يعد متاحًا أو تعذر العثور عليه.
- `REMOVED`: تم حذفه عمدًا مع الاحتفاظ بأثر تاريخي.

من الآن لا نستخدم `storage_provider: PENDING` للحالات الجديدة؛ القيمة الرسمية هي:

`storage_provider: GOOGLE_DRIVE`

وإذا لم يرفع الملف بعد:

`asset_binding_status: PENDING_UPLOAD`

## قاعدة رفع الصور

بعد موافقة المستخدم على التسجيل:

1. أنشئ Case ID النهائي.
2. أنشئ/استخدم مجلد السنة.
3. أنشئ مجلدًا باسم Case ID.
4. لكل صورة متاحة فعليًا في المحادثة، ارفعها إلى مجلد الـCase إن كانت الأدوات تسمح بالوصول إلى bytes/file reference.
5. سجّل Google Drive File ID واسم الملف والمجلد في Asset Record.
6. إذا الصورة ظاهرة في تاريخ الشات لكن bytes غير متاحة للأداة، **لا تدّعِ رفعها**؛ سجلها `PENDING_UPLOAD` مع وصفها وموضعها في المحادثة.
7. لا تعيد استخراج الشات من الصفر لاحقًا؛ يتم فقط استكمال ربط الـAsset ID بالصورة.

## قاعدة الاستدعاء

عندما يطلب المستخدم استدعاء تصميم أو حالة قديمة:

1. ابحث في `CASES/` أولًا باستخدام Case ID أو Order ID أو الكلمات المفتاحية أو نوع المنتج/المقاس.
2. اقرأ الحالة كاملة.
3. اقرأ Assets Map.
4. لأي Asset بحالة `LINKED`، استخدم Google Drive File ID للوصول إلى الصورة/الملف.
5. وضّح دور كل صورة قبل استخدامها: original / reference / generated / final.
6. أعطِ الأولوية للنتيجة `FINAL_APPROVED`.
7. استخدم المرفوض فقط كـnegative learning.

## قاعدة عدم اختراع الحقيقة

- لا تعتبر آخر صورة Final إلا إذا كان هناك دليل واضح على اعتمادها.
- إذا لم توجد موافقة نهائية: `NOT_CONFIRMED`.
- لا تخترع Order ID أو اسم عميل أو مقاس أو رابط صورة.
- لا تقل إن صورة رُفعت إلى Drive إلا إذا حصلت على File ID فعلي من Google Drive.
- افصل بين `EXPLICIT` و`INFERRED` و`UNKNOWN`.

## الخصوصية

- صور العملاء لا تحفظ داخل GitHub العام.
- GitHub يحفظ الـmetadata والـCase records وقواعد التعلم فقط.
- الصور الفعلية تحفظ في Google Drive.
- لا تحفظ Tokens أو Secrets أو Signed URLs سرية داخل Case.

## أولوية التعلم

`FINAL_APPROVED > EXPLICITLY_LIKED > PARTIAL_ACCEPTANCE > REJECTED`

المرفوض لا يُحذف؛ يبقى كخبرة سلبية.
