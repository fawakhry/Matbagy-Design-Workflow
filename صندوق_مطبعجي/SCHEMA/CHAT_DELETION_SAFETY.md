# Chat Deletion Safety Protocol — صندوق مطبعجي

## الهدف

المحادثات مع ChatGPT أو Gemini قد تكون مؤقتة ويمكن للمستخدم حذفها. لذلك لا يجوز اعتبار تاريخ الشات نفسه ذاكرة دائمة.

المصدر الدائم الوحيد لقرارات وتصميمات صندوق مطبعجي هو GitHub + Google Drive assets وفق القواعد الرسمية.

## القاعدة الأساسية

قبل أن يعتبر أي Agent أن جلسة يمكن حذفها بأمان، يجب أن تكون كل المعلومات المهمة التي ظهرت فيها قد تم حفظها في المصدر الدائم المناسب.

## ما الذي يجب حفظه؟

عند وجود Case معروفة، يجب تحديث ملفات الغرفة المناسبة قدر الإمكان:

- `ROOMS/YYYY/<CASE_ID>/STATUS.md`
- `ROOMS/YYYY/<CASE_ID>/CHATGPT.md`
- `ROOMS/YYYY/<CASE_ID>/GEMINI.md`
- `ROOMS/YYYY/<CASE_ID>/DECISION.md`
- `ROOMS/YYYY/<CASE_ID>/SYNC_LOG.md`

ويجب تحديث Case Record نفسها إذا ظهر قرار/اعتماد/تغيير يخص الحالة الدائمة.

## Gemini

بعد أي رأي بصري أو مراجعة أو مقارنة مهمة:

1. اقرأ آخر `STATUS.md` و`CHATGPT.md` و`DECISION.md` قبل الكتابة.
2. سجل رأي Gemini في `GEMINI.md` مع Case/Asset references.
3. سجل حدث المزامنة في `SYNC_LOG.md` إن كان الوصول للكتابة متاحًا.
4. لا تعتبر رأي Gemini قرارًا نهائيًا؛ القرار النهائي للمستخدم ويسجل في `DECISION.md`.

## ChatGPT

بعد أي رأي/قرار تنظيمي أو دمج لرأي Gemini:

1. اقرأ آخر `STATUS.md` و`GEMINI.md` و`DECISION.md`.
2. سجل الرأي/الخلاصة في `CHATGPT.md`.
3. سجل حدث المزامنة في `SYNC_LOG.md` إن كان الوصول للكتابة متاحًا.
4. لا تغلق Case إلا بقرار المستخدم الواضح.

## تأكيد الحفظ

إذا كان Agent لديه وصول كتابة فعلي إلى GitHub، لا يقل `SAFE_TO_DELETE_CHAT` إلا بعد نجاح الكتابة والحصول على دليل provider مثل commit/update success.

إذا لم يكن لديه وصول كتابة فعلي أو فشل الحفظ، يجب أن يقول بوضوح:

`NOT_SAFE_TO_DELETE_CHAT — PERSISTENCE_NOT_CONFIRMED`

ولا يدعي أن المعلومات محفوظة.

إذا احتاج المستخدم حذف الشات رغم عدم وجود write access، يجب على Agent إخراج `PERSISTENCE_BLOCK` منظم يحتوي كل المعلومات الجديدة المطلوب نقلها إلى GitHub في جلسة/أداة لديها صلاحية كتابة.

## الاستدعاء بعد حذف الشات

في أي جلسة جديدة:

1. لا تعتمد على ذاكرة الشات القديم.
2. ابدأ من `صندوق_مطبعجي.md` ثم `اقرأني_أولاً.md`.
3. حدد Case المطلوبة.
4. اقرأ Case Record + Room files + Assets map.
5. استكمل من آخر حالة محفوظة فقط.

## منع فقدان الحقيقة

- لا تحفظ Final Approval لمجرد أن آخر نسخة تبدو نهائية.
- لا تخترع timestamps أو IDs أو روابط.
- لا تقل إن Sync تم إلا إذا تم فعليًا.
- عند الشك استخدم `UNKNOWN` أو `PERSISTENCE_NOT_CONFIRMED`.
